## Starting Point

The port of Humanoid-Goalkeeper (G1/Isaac Gym) to Booster T1 (mjlab/MuJoCo) had a checkpoint at `model_1200.pt` from run `2026-06-10_11-43-09`. Training showed two major symptoms:
1. **Hands not being used** — `hand_proximity_strict` reward was near-zero throughout training
2. **Policy divergence** — entropy rising 22→26+, std rising 0.63→0.78, AMP reward collapsing after iter 744

The session diagnosed all root causes, implemented fixes, then ran two rounds of independent subagent audits (8 agents in parallel, then 9 agents in parallel) to verify every change against G1 upstream.

## Architecture Context

### G1 upstream (Isaac Gym / HIM-PPO)
- Single shared Adam optimizer — actor, critic, AND all 6 AMP discriminators update in the same `loss.backward()` + `optimizer.step()` call
- `him_ppo.py` line 116: one `optim.Adam(params, lr=1e-3)` where `params` includes everything
- Discriminator gets exactly `num_learning_epochs × num_mini_batches = 1 × 4 = 4` gradient steps per iteration
- No gradient clipping on discriminator (only actor-critic is clipped at `max_grad_norm=1.0`)
- `upper_body_link = "pelvis"` (g1_29_config.py:180) — pelvis world-frame Y velocity used for vel_sigma
- `amp_coef = 0.4` (g1_29_config.py:364)
- `entropy_coef = 0.01` (g1_29_config.py:369)
- Reward weights: `eereach=10`, `success=5`, `stopball=100` — all scale by `(1 + 0.5 * curriculumupdate)` giving eereach peak=25
- `end_regions` assign each env permanently to one of 6 motion types at init — even regions (0,2,4) → left hand, odd (1,3,5) → right hand
- `approachidx` snap in `post_physics_step` lines 203–206: when ball_x_local ∈ (0.1, 0.5) and not deflected, overwrites `end_target` with live ball position and clips X to [origin+0.1, origin+1.0]
- `_reward_eereach` NEVER reads live ball position — only reads `self.dist = norm(end_target - hand)` which was pre-computed using `end_target`
- SpectralNorm class is defined in `amp.py` but never applied — dead code; discriminator uses plain `nn.Linear`
- Effective gradient penalty lambda = 5.0 × 0.1 (call-site multiplier) = **0.5**

### Port (mjlab / MuJoCo)
- SEPARATE discriminator optimizer — `disc_optimizer = optim.Adam(disc_params, lr=...)` independent from PPO
- Discriminator updates run AFTER the PPO `alg.update()` call, not interleaved
- 6 discriminators (one per motion type): lefthand, righthand, leftjump, rightjump, leftstep, rightstep
- Static partition (`static_partition=True`): each env permanently assigned to one motion type
- Ball approaches from +X; robot faces +X; left side = +Y, right side = -Y

## Changes Made (11th-pass, commit `60f3893`)

### commands.py — `_resample_command`

**Change: RSI → standing pose initialization**

BEFORE: wrote motion-data frame 0 into sim at every episode reset (Reference State Initialization). Also added a 0.05m Z offset to compensate for motion data being 8cm below sim floor.

AFTER: writes `robot.data.default_root_state` (T1_STANDING_KEYFRAME) + `default_joint_pos` with zero velocity. Pose/velocity/joint-position noise from cfg still applies. `reset_robot=False` kwarg added so mid-episode clip-loop calls skip the reset entirely.

WHY: G1 `_reset_dofs` (line 677) uses `self.standpos`; `_reset_root_states` (line 702) uses `base_init_state`. Motion data is consumed only inside the AMP runner replay buffer — never written to sim at reset. RSI was inherited from mjlab tracking framework, not from G1 design.

AUDIT RESULT: ✅ LOGICAL — confirmed by independent agent reading G1 lines 657–735.

---

### commands.py — `_update_command`

**Change: Added approachidx snap**

BEFORE: `_ball_end_target` was set once at episode reset in `_reset_ball` as a linear interpolation along the ball's chord: `ball_start + (ball_end - ball_start) * catch_prop`. Never updated mid-episode.

AFTER: New block in `_update_command`. Every step:
1. Computes `ball_x_local = ball_pos_w[:, 0] - env_origins[:, 0]`
2. Checks `not_deflected = (ball_x_vel - _sb_init_vx) < 2.0`
3. If `ball_x_local ∈ (0.1, 0.5)` AND not deflected: overwrites `_ball_end_target[approachidx]` with live ball position
4. Clips `_ball_end_target[:, 0]` to `[env_origin_x + 0.1, env_origin_x + 1.0]` for ALL envs

WHY: G1 lines 203–206 in `post_physics_step`. The frozen linear-interpolation estimate has Z-error from gravity (parabolic arc ≠ chord). Without the snap, both `eereach` and `hand_proximity_strict` reward the hand for reaching a phantom point that can be tens of cm from the real ball.

MINOR NOTE: `_sb_init_vx` is populated lazily (first step of each episode by `stopball` reward). On the very first episode of training it is `None`, causing the deflection check to be skipped (all envs treated as not-deflected). Safe fallback — lasts at most one episode.

AUDIT RESULT: ✅ LOGICAL — port mirrors G1 lines 203–206 exactly. Deflection check `(current_vx - init_vx) < 2.0` is semantically identical to G1's `self.ball_states[:,7] - self.ball_vel < 2.0`.

### rewards.py — `eereach` Phase 2 target

**Change: Always use end_target, not a distance-threshold toggle**

BEFORE: selected between `end_target` (for ball_x_local > 0.5) and live `ball_pos_w` (for x_local ≤ 0.5).

AFTER: `target_pos = end_target if end_target is not None else ball_pos_w` — always uses the frozen intercept (kept accurate by approachidx snap).

WHY: G1 `_reward_eereach` NEVER reads `ball_pos_w`. It only reads `self.dist` which is always `norm(end_target - hand)`. The BEFORE logic was backwards — it was switching to live ball exactly in the 0.1–0.5 m window where approachidx snap makes `end_target` most accurate.

AUDIT RESULT: ✅ LOGICAL — and the BEFORE version was confirmed wrong by independent agent.

---

### rewards.py — `eereach` and `hand_proximity_strict` hand selection

**Change: Region-based selection (`type_ids % 2`) instead of `min()`**

BEFORE: `min_dist, closest_idx = dist_to_target.min(dim=-1)` — whichever hand was physically closer.

AFTER: `hand_idx = (type_ids % 2).long()` — even motion types (0,2,4 = left side) → left hand (`body_ids[0]`); odd types (1,3,5 = right side) → right hand (`body_ids[1]`). Falls back to `argmin()` if `motion_type_ids` unavailable.

Applied to both `eereach` and `hand_proximity_strict`.

WHY: G1 lines 209–223 assign hands by region mask, locked for the entire episode. `min()` allows mid-episode hand flips — if the off-hand is 2cm closer at one step, the reward suddenly trains the wrong arm. With `static_partition=True` each env is permanently assigned to one motion type; rewarding the wrong arm sends contradictory gradients.

Port motion types exactly mirror G1 region numbering:
- Even (0,2,4) = left side (+Y) → left hand = body_ids[0]
- Odd (1,3,5) = right side (-Y) → right hand = body_ids[1]

AUDIT RESULT: ✅ LOGICAL — G1 lines 209–223 confirmed even→left, odd→right.

### rewards.py — `eereach` vel_sigma

**Change: Pelvis world-frame Y velocity (G1 exact match)**

BEFORE (10th-pass had switched to hand velocity): `closest_vel = (hand_vel * to_target_unit).sum(-1)` then `1 + 3*clamp(closest_vel, 0, 3)`.

AFTER:
```python
direction = +1 for even types (left side, dive left = +Y)
direction = -1 for odd types (right side, dive right = -Y)
base_vel_sigma = 1 + 3 * clamp(direction * root_link_lin_vel_w[:, 1], 0, 3)
jump_vel_sigma = 1 + jump_scale * clamp(root_link_lin_vel_w[:, 2], 0, 3)
```

WHY: G1 lines 1381–1388 use `rigid_body_states[:, upper_body_index, 8]` (world-frame Y velocity of pelvis). `upper_body_index` resolves to "pelvis" (g1_29_config.py:180). Port's `root_link_lin_vel_w[:, 1]` = world-frame Y velocity of root body (Trunk = pelvis in T1). They are functionally identical.

G1 direction coding:
- Regions 0/4 (+Y ball side): `1 + 3*clip(vy, 0, 3)` — rewards positive Y velocity
- Regions 1/5 (-Y ball side): equivalent to `1 + 3*clip(-vy, 0, 3)` — rewards negative Y velocity

Port `direction * vy` is algebraically identical.

AUDIT RESULT: ✅ LOGICAL — mathematically proven identical to G1 by independent agent.

### rewards.py — `hand_proximity_strict` target

**Change: Frozen end_target instead of live ball**

BEFORE: `dist = norm(hand - ball.root_link_pos_w).min()` — live flying ball.

AFTER: measures to `env._ball_end_target` (frozen intercept, kept accurate by approachidx snap). Falls back to live ball if `_ball_end_target` not set.

WHY: ball at 4 m/s crosses 0.15m in ~37 ms (1–2 steps at 50Hz). The live-ball version almost never fired. G1 `_reward_success` line 1403: `(self.dist < strict_th)` where `self.dist = norm(end_target - hand)`.

AUDIT RESULT: ✅ LOGICAL — G1 confirmed by independent agent.

### discriminator.py

**Change: Removed spectral_norm, fixed docstring**

BEFORE: `spectral_norm(nn.Linear(...))` for all layers.

AFTER: plain `nn.Linear()` throughout. Gradient penalty (λ=5.0 × 0.1 at call site = effective λ=0.5) remains.

WHY: G1 `amp.py` defines `SpectralNorm` class (lines 26–80) but never applies it — dead code. All discriminator layers use plain `nn.Linear` (lines 103, 108, 113). Port now matches G1 exactly.

Also fixed misleading docstring: comment claimed "removed erroneous * 0.1 multiplier" but the `* 0.1` is still present at the runner call site (effective lambda = 0.5, matching G1). Corrected to accurately state 0.5 is intentional.

AUDIT RESULT: ✅ LOGICAL — SpectralNorm confirmed as dead code in G1.

### him_amp_runner.py

**Changes: disc updates 20→4, grad clip added**

`num_disc_updates` changed from `num_mini_batches * num_learning_epochs` (4×5=20) to `num_mini_batches` (4).

Added `clip_grad_norm_(disc_params, max_norm=1.0)` after disc backward.

WHY for 4 steps: G1's 20 steps are joint actor+critic+discriminator steps inside one shared optimizer backward — not 20 pure disc steps. A separate disc optimizer running 20 pure steps per iteration after the policy has already updated allows the discriminator to overfit before the policy can respond. 4 steps (matching G1's actual count) prevents this.

WHY grad clip: adds stability safety net for a separately-optimized discriminator. G1 doesn't clip discriminator (benefits from shared optimizer regularization), but an independent optimizer can produce large gradient spikes.

AUDIT RESULT: ✅ LOGICAL.

## 12th-Pass Corrections (commit `229f06b`)

Three overcorrections found by second-round subagent audit (9 agents in parallel).

### Fix 1 — disc LR: 1e-5 → 1e-4

PROBLEM: `lr=1e-5` makes the discriminator ~100× slower than G1's effective pace. At `1e-5` the discriminator output stays near-random for hundreds of iterations — AMP reward becomes a constant flat bonus (`clamp(1 - 0.25*(d-1)^2, 0) ≈ 0.75` uniformly) with no motion-shaping signal.

ROOT CAUSE OF ORIGINAL MISTAKE: disc overtake at iter ~700 was caused by 20 PURE disc steps per iteration — not by lr=1e-4. Reducing to 4 steps was the correct fix. Simultaneously lowering LR was a double-correction.

FIX: `lr=1e-4`. 4 steps at `1e-4` = port disc runs at ~10× slower pace than G1. Conservative enough against dominance, still capable of learning.

SUBAGENT VERDICT: NOT LOGICAL at 1e-5. Reverted to 1e-4.

---

### Fix 2 — entropy_coef: 0.005 → 0.01

PROBLEM: stated justification ("prevents entropy explosion when AMP reward collapses") is mechanically wrong. `entropy_coef` enters the PPO loss as `- entropy_coef * entropy.mean()` (`him_ppo.py` line 229) — zero interaction with AMP reward or discriminator training. Entropy explosion is caused by the policy failing to find good actions; it cannot be prevented by reducing the entropy bonus coefficient.

Real risk of `entropy_coef=0.005` is premature convergence — at 40k iterations the policy needs exploration pressure for 35k iters after any early local optimum. The adaptive KL schedule (`desired_kl=0.01`) is the correct mechanism for preventing update-size explosions.

FIX: revert to 0.01 (G1 upstream, `g1_29_config.py` line 369).

SUBAGENT VERDICT: NOT LOGICAL. Both discussion agents agreed: revert to 0.01.

---

### Fix 3 — eereach 30→20, hand_proximity_strict 15→10

PROBLEM: eereach=30 exceeds G1's curriculum PEAK of 25.0. The port's BASE starts harder than G1 ever gets. eereach:stopball ratio = 30:100 = 0.30 vs G1's constant 0.10 — 3× overweighted.

FIX:
- eereach base: 30→20 (2× G1 base). Curriculum: 20/30/40.
- hand_proximity_strict base: 15→10 (2× G1 base of 5). Curriculum: 10/15/20.
- Resulting ratio at base: eereach:stopball = 20:100 = 0.20 (2× G1's 0.10 — proportionate to halved AMP).

SUBAGENT VERDICT: DIRECTION LOGICAL, MAGNITUDE NOT LOGICAL. eereach:stopball ratio 0.30 was 3× G1; new 0.20 is 2× (proportionate to amp_coef being halved).

---

### Non-change: amp_coef stays at 0.2

Two discussion agents disagreed:
- **G1 researcher:** revert to 0.4 — disc at `lr=1e-4`/4 steps is already ~10× slower than G1; 0.2 eliminates AMP signal
- **Port implementer:** keep at 0.2 — T1 arm posture is asymmetric (counterbalance right arm in default pose); motion data quality for T1's specific arm morphology is unverified

Decision: **keep amp_coef=0.2** pending verification that motion reference data correctly represents T1's catching arm postures. Review after first successful training run.

## Key Debugging Reference

### What to watch in WandB during training

| Metric | Expected early (0–2k iter) | Red flag |
|--------|--------------------------|----------|
| `disc_loss` | Slowly decreasing from ~4–5 toward 1–3 | Stuck at 4+ after 2k iters = disc undertrained; stuck at 0 = disc overtrained |
| `mean_amp_reward` | Should rise from ~0.3 and stabilize | Collapses to ~0 = discriminator winning |
| `hand_proximity_strict` | Should appear above 0 within first 500 iter | Stays at 0 = frozen end_target not being reached |
| `entropy` | Stable or slowly decreasing around 22–24 | Rising to 26+ = policy diverging |
| `std` | Stable around 0.6–0.7 | Rising to 0.8+ = entropy explosion |
| `stopball` | Should rise after first 1k iter | Flat at 0 throughout = robot not saving at all |

### Root causes of prior failures

**Failure mode 1: hands never reach ball**
- Old cause A: `hand_proximity_strict` measured to live ball (ball crosses 0.15m in 1–2 steps, never triggers)
- Old cause B: `min()` hand selection allowed wrong hand to be rewarded mid-episode
- Old cause C: Missing approachidx snap → frozen target had Z-error from parabolic arc ≠ chord
- Fixed by: frozen end_target + region hand selection + approachidx snap

**Failure mode 2: AMP reward collapse / policy divergence**
- Old cause A: 20 pure disc steps per iteration → discriminator overtook policy (disc_loss spiked to 4.2 at iter 744)
- Old cause B: disc LR 1e-5 (overcorrection) → discriminator too slow to learn any signal
- Old cause C: entropy_coef 0.005 → premature convergence risk at 40k iters
- Fixed by: 4 disc steps + lr=1e-4 + entropy_coef=0.01

**Failure mode 3: arms not extending correctly**
- Old cause: torso lateral velocity gave no gradient for arm extension
- First wrong fix: hand velocity toward target (loses full-body dive signal, G1 uses pelvis)
- Correct fix: pelvis Y velocity with direction sign (mathematically identical to G1)
