## Bug 1 (PRIMARY TRAINING KILLER): `dof_vel_limits` formula

### G1 upstream (`legged_robot.py:1550`)
```python
def _reward_dof_vel_limits(self):
    return torch.sum(
        (torch.abs(self.dof_vel) - self.dof_vel_limits * self.cfg.rewards.soft_dof_vel_limit).clip(min=0.),
        dim=1,
    )
# soft_dof_vel_limit = 0.9, per-joint URDF velocity limits (~20 rad/s for T1 legs)
# Formula: LINEAR penalty above 20*0.9 = 18 rad/s threshold
```

### ILB (faithful port of G1)
```python
def dof_vel_limits(env, vel_limit=20.0, soft_factor=0.9, ...):
    out_of_limit = (joint_vel.abs() - vel_limit * soft_factor).clamp(min=0.0)
    return out_of_limit.sum(dim=-1)   # LINEAR, threshold = 18 rad/s
```

### ObsHis (buggy state before fix)
```python
def dof_vel_limits(env, vel_threshold=10.0, ...):
    excess = torch.clamp(vel.abs() - vel_threshold, min=0.0)
    return excess.pow(2).sum(dim=-1)   # SQUARED, threshold = 10 rad/s
```

Two divergences from G1:
1. **Threshold 10 rad/s instead of 18 rad/s** — fires on normal joint motion during falls
2. **Squared instead of linear** — amplifies signal enormously

Penalty at vel = 15 rad/s per joint:
- ILB/G1: `(15 - 18).clamp(0) = 0` → no penalty
- ObsHis: `(15 - 10)² = 25 × weight -2.0 = -50 per joint`

Over a 7-step crashed episode: dof_vel_limits alone produced `-30`, swamping all positive rewards and making advantage estimation impossible.

### Fix
`mdp/rewards.py`:
```python
def dof_vel_limits(
    env: "ManagerBasedRlEnv",
    vel_limit: float = 20.0,
    soft_factor: float = 0.9,
    asset_cfg: SceneEntityCfg = _DEFAULT_ROBOT_CFG,
) -> torch.Tensor:
    robot: Entity = env.scene[asset_cfg.name]
    vel = robot.data.joint_vel[:, asset_cfg.joint_ids]
    out_of_limit = (vel.abs() - vel_limit * soft_factor).clamp(min=0.0)
    return out_of_limit.sum(dim=-1)   # LINEAR, 18 rad/s threshold
```
`tasks/goalkeeper_env_cfg.py` params updated:
```python
params={"vel_limit": 20.0, "soft_factor": 0.9, "asset_cfg": _ALL_JOINTS_CFG}
```

## Bug 2 (ARCHITECTURE): `cur_obs` extracted from wrong slice of term-major history

### G1 history layout — time-major (`legged_robot.py:430`)
```python
self.obs_buf = torch.cat((self.obs_buf[:, self.num_one_step_obs:], current_actor_obs), dim=-1)
```
Rolling left-shift buffer. Layout after 10 frames:
```
[all_terms_t0 | all_terms_t1 | ... | all_terms_t9]
  ← 86 ——→     ← 86 ——→            ← 86 ——→
```
So `obs_buf[:, -86:]` = the most-recent single-frame observation ✓

### G1 actor (`actor_critic.py:232`)
```python
actor_input = torch.cat((
    obs_history[:, -self.num_one_step_obs:],   # ← relies on time-major layout
    history_latent,
    self.estimate_ball,
    torch.argmax(self.estimate_region, dim=-1, keepdim=True),
), dim=-1)
```

### mjlab history layout — term-major

mjlab `CircularBuffer` maintains a separate per-term buffer. When multiple terms share `history_length=10`, each term gets its own 10-frame ring buffer. The observation manager (line 357–379) concatenates them in term order:

```
[term1_h0..h9 | term2_h0..h9 | ... | termN_h0..h9]
  ← d1×10 —→   ← d2×10 —→         ← dN×10 —→
```

For the 12-term actor group (dims `[3,3,3,21,21,21,3,3,3,3,1,1]` = 86, history_length=10 = 860 total):
```
[base_lin_vel ×10 (30) | base_ang_vel ×10 (30) | projected_gravity ×10 (30) |
 joint_pos_rel ×10 (210) | joint_vel ×10 (210) | actions ×10 (210) |
 ball_pos_b ×10 (30) | ball_vel_b ×10 (30) | left_foot_pos_b ×10 (30) |
 right_foot_pos_b ×10 (30) | motion_type_id ×10 (10) | ball_landing_y ×10 (10)]
```

`full_history[:, -86:]` = dims [774:860]:
- `ball_vel_b` frames 8–9 only (6 dims, partial)
- `left_foot_pos_b` all 10 frames (30 dims)
- `right_foot_pos_b` all 10 frames (30 dims)
- `motion_type_id` all 10 frames (10 dims — constant value, useless)
- `ball_landing_y` all 10 frames (10 dims)

The actor was making decisions using historical foot position data and constant zone IDs, not the current joint angles, robot velocity, or ball state. The network had to learn everything through `history_latent` (16D) and `ball_est` (6D) — 22/109 meaningful actor input dims.

### Fix

`him_actor.py` — added `_extract_cur_obs()`:
```python
def _extract_cur_obs(self, full_history: torch.Tensor) -> torch.Tensor:
    """Extract most-recent single-frame obs from mjlab's term-major history layout.
    For each term with single-frame dim d_i, block = d_i × H dims.
    Newest frame = last d_i elements of that block.
    """
    if not self._term_dims:
        return full_history[:, -self.num_one_step_obs:]  # fallback: G1 time-major assumed
    H = self.history_length
    cur_parts = []
    offset = 0
    for d in self._term_dims:
        block_end = offset + d * H
        cur_parts.append(full_history[:, block_end - d : block_end])
        offset = block_end
    return torch.cat(cur_parts, dim=-1)  # (N, num_one_step_obs)
```

`him_amp_runner.py` — derives `term_dims` from observation manager and passes to actor:
```python
_obs_mgr  = getattr(_base_env, "observation_manager", None)
_hist_dims = _obs_mgr.group_obs_term_dim.get("actor", [])
_term_dims = [int(d[0]) // history_length for d in _hist_dims]
# → [3, 3, 3, 21, 21, 21, 3, 3, 3, 3, 1, 1]
him = HimActorModel(..., term_dims=_term_dims)
```
